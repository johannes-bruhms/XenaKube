# Synthesis Bridge — Max/MSP + SWAM Cello

Detailed reference for the synthesis layer: SWAM Cello 3 (Audio Modeling physical-modeling VST) driven via MIDI from a Max/MSP bridge on port 57121. **The load-bearing summary lives in CLAUDE.md as the Bridge Invariants table** — that's the part Claude must apply on every change. **Full enforcement detail per invariant** (Scope / Enforcement / Telemetry) lives in **`docs/bridge-invariants.md`** — read it before changing code that touches any invariant. This file is the patch / routing / MCP reference: patch topology, file roles, mapping cheat sheet, MCP bridge integration. Read when you're touching `max/xk_swam.js`, the `.maxpat`, the SWAM preset, or any of the per-complex routing.

## Single-instance model

One `[vst~ "SWAM Cello 3"]` downstream of the v8. Each `/xk/voice` renders its full gesture into that one plugin; a new voice hard-steals the current one (CC 11 = 0 + CC 120 + CC 123 + tracked noteOffs). Reason: SWAM's Ambiente panel auto-registers every loaded VST instance as a reverb source regardless of which ones receive MIDI, summing identical sources into audible phase overlap — pooled instances sound like multiple cellos even when only some receive MIDI. Single-instance also drops Max DSP CPU ~8×.

`POOL_SIZE = MAX_ACTIVE = 1` in `xk_swam.js`. The allocator / `stealInstance` / `makeInstance` machinery is retained as the per-voice bookkeeping anchor (every phrase generator takes `inst` as first arg, reads its `ccCache` / `activeNotes` / `phraseTasks` / face snapshots / status). To re-enable polyphony: raise both constants, add `[poly~ swam_voice @voices N]`, and re-add `outlet(MIDI_OUTLET, "target", inst.voice)` before the `midievent` emit in `emitMidi`.

## Patch Topology

Runtime patch: `max/xenakube_swam.maxpat` (open in Max 9+).

```
[udpreceive 57121] → [gate] → [v8 xk_swam.js @autowatch 1] → outlet 0 → [vst~ "SWAM Cello 3"] → DSP chain → [dac~]
                                                             outlet 1 → (debug — attach [print xk_swam])
                                                             outlet 2 → [udpsend 127.0.0.1 57122]   (MIDI echo to relay)
                                                             outlet 3 → (detected moves — `face <L|L'|...>` per quarter-turn, `algorithm <name>` per cube-algorithm match; wire to [route face algorithm])

[loadbang] ┬── [max_active 1] → v8 inlet
           └── [read xenakube_main.swam] → [vst~]
```

DSP chain after `[vst~]`: `[abl.dsp.compander~ @shape 0.15] → [live.gain~] → [abl.device.drumbuss~] → [abl.dsp.compander~ @shape 0.2] → [abl.device.limiter~] → [dac~]`, with a `[live.scope~]` tap. The `[gate]` between `udpreceive` and the v8 lets the performer mute incoming OSC for offline inspection without closing the relay.

The MIDI echo on outlet 2 emits pre-formatted OSC `/xk/midi/{noteon,noteoff,bendstep,expr,panic}` messages — no `[prepend]` or `[route]` needed; `udpsend` packages them natively. `noteon`/`noteoff` payload is `(voice, pitch, velocity, complex)` where `complex` is `inst.activeComplex` at echo time; the dashboard piano-roll uses it for color and gliss-curve rules. `expr` payload is `(voice, ccVal, complex, planId)` — fired from `cc()` / `ccForce()` whenever `num === CC.EXPRESSION` so the dashboard can size brushes by the audible dynamic curve (D47 ramps CC 11 linearly across a phrase) rather than per-note velocity (a poor proxy for SWAM's ongoing loudness). Pure additive telemetry — no synthesis state depends on it.

Optional spectrogram routing is separate from the SWAM control path. `pfft-test.maxpat` hosts the stock-Max analyzer harness, and `xenakube_swam.maxpat` also contains a toggle-gated analyzer sender for the performance host: `[receive~ xk_spectrum_tap]` or `[adc~ 1 2]` feeds `[pfft~ xk_pfft_spectrum 1024 4]`, the subpatch writes magnitudes into `buffer~ xk_fft_mag`, and a 30 Hz `qmetro` reads positive FFT bins into `xk_spectrum.js` as `rawbins`. The helper reduces them to compact log bins and emits `/xk/spectrum/frame` through `[udpsend 127.0.0.1 57122]`; the sender is optional telemetry and does not change the thin SWAM bridge routing. When a frame carries `complex=0`, the relay colors it from the latest audio-side `/xk/midi/noteon` echo so reverb or phrase tails keep their old modality until the new phrase actually sounds.

The SWAM instance's preset is set manually inside the SWAM GUI (saved as `xenakube_main`).

## Mapping Cheatsheet

- **Complex → technique** (COMPLEX table): C1 Pizz, C2/C3 Arco, C4 Harmonics (CC 78), C5–C7 Portamento, C8 near-bridge + Tremolo (CC 79). Per-complex register clamps are disabled/commented out, and face grammar no longer applies register transpose or forced pitch direction; sieve position, phrase-local anchor rolls, and global cello-range folding choose the pitch. C3/C4/C7/C8 keep their local gesture shapes around an anchor, but that anchor is selected from the current sieve rather than pinned to the middle register. Each complex still owns `tremoloRate` baseline (CC 80), per-stage `exprEnv.{attackRampMs, sustainRampMs, releaseRampMs}`, and a `bowPoly` mode. Current C5–C7 gliss use Double/Hold plus `slideViaBend=true`; pitchbend, not SWAM Mono Poly Release, produces the slides.
- **C4 harmonic mode → tetra-orbit parity**: `harmonicsForC4(tetra: 0|1)` returns OCT (even tetra) or OCT_5TH (odd tetra) per voice. CTRL is reserved for algorithm-driven pings (not reachable via per-voice rotation since V1/V2 retired); OFF reserved for non-C4 complexes.
- **Intensity → 5 scalars** (8-level INTENSITY_MAP, ppp..fff): Expression peak, note velocity, bow-pressure scalar, phrase density, tremolo-rate scalar. ppp sits at SWAM's audibility floor (CC 11 ≈ 15 / Expression slider 0.12 of 1.0); fff hits the MIDI ceiling (CC 11 = 127). One unique dynamic per cube vertex; K_i permutation shuffles position-to-intensity mapping. Turn-rate pressure can bend these scalars upward, but the K vertex remains the baseline.
- **Face → gesture shape** (Phase A1 Temporal Identity): `/xk/face <face>` populates `state.face*` from `FACE_MAP` for duration, envelope, articulation, release, and velocity contour only; `registerBias` and `motion` are metadata and the live pitch path ignores them. `handleVoice` snapshots the usable face fields onto the allocated `inst` so face changes don't retroactively reshape an in-flight phrase. `phraseC1..C8` consult `faceShapedCount(inst, lo, hi, forGliss)`: `ENV_PROFILE.isSingle` (pluck/stab/drone) collapses non-gliss complexes to a single note; gliss complexes (C5/C6/C7) get `forGliss=true` with a hard minimum of 1 subsequent slide (see Bridge Invariants in CLAUDE.md). `ENV_PROFILE.countMult` (burst ×1.8) thickens density; `stepVelScale` shapes per-step velocity (swell cresc, fade dim, stab/burst accent-first). C2/C6 sieve-walk direction comes from the shared walker state and boundary flips, not the face. `scheduleExprEnvelope` scales attack/peak/sustain by `ENV_PROFILE.{attackCoef, peakCoef, sustainCoef}`.
- **Half-turn → punctuation**: `/xk/voice` carries a final `halfTurn` int. When it is 1, `handleVoice` bypasses the normal K/C/face phrase path and calls `setupHalfTurnGesture` + `phraseHalfTurn`: short fff bowed accent dyad, max Expression, high bow pressure, no gliss/arc expectation. The original complex number remains on MIDI echoes for color/audit context. `inst.forceComplexSetup` forces the next normal voice to reassert its complex selectors even if the complex number repeats.
- **Duration discipline**: incoming K_i `duration` is the base phrase span. Face moves multiply it by `FACE_MAP.durationMult`; `COMPLEX_DURATION_FLOOR_SEC` protects identity-bearing complexes from being compressed below recognisable length; `MAX_PHRASE_DURATION_SEC` caps at 30 s. Every `phraseCX` calls `scheduleRelease(inst, dur)` with that resolved span, so a voice's sounding time is `duration + fade`.
- **Turn-rate pressure**: `turnRatePressure = clamp((turnRate - 0.3) / (3.0 - 0.3), 0, 1)`. Per-complex `RATE_*` gains from `src/swam-mapping.ts` raise density high bounds, C1/C4 event rates, C7 non-single drift count, base note velocity, CC 11 peak, bow pressure, C8 tremolo steady rate, and C5 bow-pressure accent. C8 has zero density gain; C6/C7 density gains are deliberately small. This makes fast turning louder/denser without erasing the K_i density/intensity identity.
- **Tilt** -> Bow Position inside the lower-half CC 16 window (`0..64`), using the EMA-smoothed +/-30 tilt jitter around each complex baseline plus scramble bias before clamping. C3 and C4 skip this stream while their phrase generators own CC 16/17 ramps; C8 skips tilt and only the deliberate scramble bias can move it.
- **Spin** → stored / dashboard activity only. It is not currently mapped to SWAM vibrato, CC 80, or bow pressure.
- **Deviation** → stored / snap telemetry only. It is not currently mapped to SWAM bow pressure.
- **Regime** → Attack Ramp multiplier (contemplative 1.2 / conversational 1.0 / burst 0.5) and Expression-ramp multiplier (contemplative 1.5 / conversational 1.0 / burst 0.4). Regime is a discrete label; turn-rate pressure is the continuous scalar.
- **Tremolo Min Speed (CC 80)**: per-phrase stochastic envelope. Each tremolo voice rolls 1/3 slow→fast / 1/3 fast→slow / 1/3 steady at onset; ramps driven by `rampCC` over `duration * 1000` ms.
- **Wild gliss density floor (D49)**: `phraseC5` requested count is `Math.max(WILD_MIN_COUNT, faceShapedCount(inst, 4, 9, true))`. `WILD_MIN_COUNT = 12` overrides the face envelope's `isSingle` collapse (pluck/stab/drone → 1) and any low-intensity rrand floor — wildness is the complex's identity, not something the face can soften. Pluck/stab/drone faces still apply their duration multiplier and `velCurve`; the salvo packs events into the resolved K-duration × face span, clipped naturally by `glissSchedule` when that span cannot fit every requested event at `MIN_GLISS_SPACING_MS = 200 ms`. K-vertex density and intensity still modulate count above the floor for non-isSingle faces. Turn-rate pressure can raise the requested high bound through `RATE_DENSITY_GAIN_BY_COMPLEX[5]`, but it cannot lower the floor.
- **Wild gliss slide velocity (D50 v2)**: `phraseC5` calls `glissStep(..., WILD_GLISS_VEL, wildAccent)` with `WILD_GLISS_VEL = 22`. Bumps slide-target velocity 4 units above default `GLISS_VEL = 18` for slight slide audibility. Critical constraint: SWAM Cello's Advanced→MIDI menu has "Portamento Control: Velocity (P.MaxTime)" — slide noteOn velocity directly scales portamento time. The original 18 sits at the bottom of that scale (max portamento time); 22 nudges up only marginally to preserve audible slides. **Do not bump WILD_GLISS_VEL aggressively** without verifying SWAM still engages portamento — D50 v1 tried vel 55 and produced "consecutive discrete notes with absolutely no portamento." Per-event attack character is now decoupled onto Bow Pressure Accent (D52, below), so further audibility work should happen there rather than by raising velocity. C6/C7 omit the override and keep default `GLISS_VEL = 18`.
- **Wild gliss bow pressure accent (D52)**: `phraseC5` passes `rateAccentValue(WILD_GLISS_BPA, 5, turnRate)` as the `accent` arg to `glissStep`; the base is `WILD_GLISS_BPA = 80` and full turn-rate pressure raises it by the C5 `RATE_ACCENT` gain. `bendStep` (or legacy `glissNote`) snaps CC 18 (Bow Pressure Accent — MIDI-Learned in `xenakube_main.swam` to SWAM's Expressivity → Bow Pressure Accent slider) at the slide event, then schedules a `BPA_RESET_MS = 100 ms` reset back to 0 after the target attack. Per-event attack emphasis without touching slide velocity, so SWAM's Velocity → P.MaxTime keeps portamento fully engaged. The 100 ms sustain holds the accent through the start of the slide envelope so SWAM's pressure response rings out before the next event arrives at MIN_GLISS_SPACING_MS = 200 ms (well clear of stacking). Steal safety: `cancelPhrase` forces CC 18 = 0 unconditionally so a steal mid-spike can't leak the accent into the next voice. C5 only — C6/C7 keep their gentle bow-continuation slide character. Tunables: raise WILD_GLISS_BPA to push attack harder; lower BPA_RESET_MS toward 30 if the accent feels too sustained, or raise toward 150 (do not exceed MIN_GLISS_SPACING_MS - 50 ms).
- **Wild gliss companion continuity**: C5 may add a safe 50% companion before the first slide, but the companion is not re-fired during `bendPending`. `completeBend` / `leapStep` re-voice it at each bend/leap target using the same fixed interval, so the double-stop can sustain through the whole gliss instead of dropping after onset. Unsafe planned paths skip the companion and log `DOUBLE STOP RANGE SKIP`; runtime range drift logs `DOUBLE STOP RANGE FAIL`. The active `phraseC5` defines `wildAccent` locally and logs `C5 WILD ACCENT FAIL` if accent resolution ever goes non-finite.
- **C6 ordered slide onset**: C6 anchor noteon fires at t=0 and its first ordered slide uses `FIRST_GLISS_MS_C6` with no extra first-slide `humanDelay`; later slides can still keep small humanization. This keeps C6 responsive to a cube turn while preserving the ordered stepped-sieve identity.
- **C7 immediate-start drift (D53)**: distinguishes C7 from C6 in *gesture* as well as timbre. Two retained changes: (1) `FIRST_GLISS_MS_C7 = 30 ms` (vs `FIRST_GLISS_MS` for C5; C6 has its own immediate ordered-slide constant) — anchor barely audible, drift starts almost immediately so C7 reads as continuous floating rather than C6's deliberate stepping; (2) `phraseC7` delta replaced from `rrand(-3, 3)` (uniform, ±3 swings, average ±1.7) to magnitude `rrand(1, 2)` with sign alternating per drift index — drifts rock around the anchor in zigzag, evoking inhale/exhale rather than wandering. Random `phraseStartSign` per phrase so phrases don't always begin in the same direction. Magnitude rrand(1, 2) caps swings between consecutive drifts at 4 semitones (was 6) and average ±1.2 keeps the character subtle. **`COMPLEX[7].portamento.time` stays at 115** (unchanged from pre-D53). The D53 v1 attempt to bump it to 250 ms/semi for "slow microtonal drift" was a bug: CC 5 clamps to 0..127 in `ccForce`, so the wire value was 127 (~127 ms/semi audio) while the dashboard mirror was set to 250 ms/semi → visual interpolated 2× slower than audio (drawn vs heard didn't line up; the chain was still drawing the slide while audio had already settled). Reverted in D53 v2. Genuinely slow drift requires pitchbend, which is shelved until v2 is reintegrated to the main XenaKube folder. **Dashboard mirror**: `PORTAMENTO_MS_PER_SEMITONE[7]` and `GLISS_PORTAMENTO_MS_PER_SEMITONE[7]` in `public/js/constants.js` are 115 (matching the bridge); keep both tables in sync with `COMPLEX[7].portamento.time` — Phase 1.3's `assertGlissSync` only catches line ↔ chain drift, not table ↔ audio drift, so manual sync is required.
- **Expression (CC 11)**: interpolated via `rampCC` slew limiter so envelope stages crossfade. **Phrase Dynamic Arc (D47, Phase 1+2; D57 pizz)** for sustained/gliss multi-note complexes C3/C4/C5/C6/C7/C8: one linear ramp across the full phrase duration via `schedulePhraseArc` — swell faces (L/F/F') cresc TO `peakExpr × ARC_CEIL`, fade/burst faces (U'/L'/R') dim FROM `peakExpr × ARC_CEIL` to `× ARC_FLOOR`. C2 is the exception: `phraseC2` realizes the arc per note through velocity, CC 11, and bow-position base, while CC 17 is sampled once per note from the voice bow-pressure baseline and held. **D47 Phase 2** chains consecutive same-direction voices within `ARC_CHAIN_GAP_MS = 1000 ms` — the new arc inherits `ccCache[CC.EXPRESSION]` instead of `ccForce`-snapping, so a long swell across multiple cube turns is one continuous dynamic. **D57 pizz**: C1 uses static `ccForce(CC.EXPRESSION, peakExpr)` at phrase start (per-pluck velocity is the dynamic; the legacy 3-stage envelope's 25 % peak / 70 % sustain shape was meaningless for rapid pluck clusters). isSingle face envelopes on multi-note complexes resolve to one note → legacy 3-stage path. `ARC_FLOOR = 0.30` / `ARC_CEIL = 1.00` headline tunables. See Bridge Invariants in CLAUDE.md.
- **C3 within-note bow motion**: `phraseC3` samples the current CC 11 at each note onset, calls `scheduleC3BowMotion` before the noteOn, and ramps CC 16 (Bow Position) plus CC 17 (Bow Pressure) from their current cached values toward nearby endpoints. CC 16 endpoints are clamped to the shared lower-half window (`0..64`). Lower onset CC 11 shortens the ramp duration, so quiet held notes move faster through pressure/position while louder notes shift more slowly. `handleExprTilt` and `handleExprScramble` skip C3 so this held-note motion is not overwritten by the global bow-position stream. Natural phrase ends log `C3 bowMotion`; missing motion logs `C3 BOW MOTION FAIL`.
- **C4 per-note bow motion**: `scheduleC4BowMotion` force-seeds each note's CC 16/17 start values and ramps to monotonic endpoints over that note's audible window. Bow Position movement stays entirely inside the lower-half `0..64` window, including the full-lower-half sweep class.
- **Cross-string slide via pitchbend (D59 + D60 + D63 + D64)**: when `sameString(src, dst)` is FALSE AND interval ≤ `PITCHBEND_RANGE_SEMI`, `glissStep` dispatches `bendStep` — pitchbend wheel ramp on the held source, then atomic `bend = 0 + noteOff(source) + noteOn(target)` at ramp end via `completeBend(inst, scheduled)`. SWAM's portamento engine can't slide cross-string (D46 baseline); pitchbend on the source's string produces an audible continuous curve regardless. Pitchbend status bytes MUST use `statusPitchbend(MIDI_CH)` with the same one-based channel convention as note/CC messages; otherwise telemetry shows bends while SWAM plays straight notes on the note channel. The bridge's `PITCHBEND_RANGE_SEMI` MUST EXACTLY MATCH the SWAM preset's Master Tuning → Pitchbend Range setting — paired tunable, mismatch silently produces audible-bend ≠ visual-bend. `bang()` logs the bridge value on every reload; cross-check against SWAM's preset every time. Bend duration capped at `MIN_GLISS_SPACING_MS - BEND_DUR_MARGIN_MS = 195 ms` to fill the inter-event window without overrun. `glissStep` entry calls `completeBend(inst, false)` for race-safety against the 5 ms margin's scheduling jitter — fires the deferred atomic transition inline before dispatching the new event. Pitchbend ramp tick = 5 ms (D64.3 — ~0.6 semis/tick at ±24, smoothly continuous). Cross-string intervals over `PITCHBEND_RANGE_SEMI` fall to `leapStep` with a `BEND CLIP` log. Per-phrase telemetry: `slides=S bends=B leaps=L`; `BEND FAIL` if `bendStep` is asked to bend a pitch not in `inst.activeNotes` (D60.1); `bend race-fix` if `completeBend` fires inline (scheduling jitter > 5 ms — if frequent, raise `BEND_DUR_MARGIN_MS`). Dashboard mirror via `/xk/midi/bendstep` OSC echo flowing through relay → WS → `triangle.bendStep` + `rolling-score.bendStep`; bend grace consumed exactly once (D62.1) to prevent cross-phrase chaining.
- **Double stops**: C2 bowed cloud, C3 hovering flat, C5/C6 gliss companions, and C8 tremolo cluster emit companion pitches via `doubleStopCompanion`, `maybeDoubleStop`, `maybeGlissDoubleStop`, or local phrase logic. Gliss companions are range-checked against the rolling-score companion window before creation and re-voiced at bend/leap completions; normal success logs `doubleStop offset=... revoices=...`, and failures log `DOUBLE STOP RANGE SKIP/FAIL` or `DOUBLE STOP FAIL`. Companions are tracked in `inst.activeNotes` and cleaned on legato overlap / release / steal. Requires Bow Polyphony = Double/Hold. Fresh companions are suppressed while a pitchbend ramp is pending so they cannot mask gliss as straight note attacks.
- **Cube-algorithm pings** route through `setupComplex(active)` for idempotent restore.
- **Flag gates** for v3.11-absent knobs: `HAS_HARMONICS_CC` / `HAS_TREMOLO_CC` / `HAS_TREMOLO_RATE` / `HAS_BOW_POLY_CC` enable CC with KS fallback (Bow Polyphony has no KS fallback — page-modifier combo); `HAS_BOW_SPEED` / `HAS_ATTACK_RAMP` / `HAS_ATTACK_CONTROL` default `false` to gate at the `cc()` helper.

## Max MCP Bridge

Claude Code can inspect and edit the running Max patch via the `maxmsp` MCP server at `MaxMSP-MCP-Server/` (registered in `.mcp.json`). **Always route patch work through the `max-patch` subagent** (`.claude/agents/max-patch.md`) — it has the MCP tools scoped and knows the XenaKube patch conventions.

**Confirm before editing the live patch** — even when running under `--dangerously-skip-permissions`, ask the user before invoking any `mcp__maxmsp__*` tool that mutates the patch (`add_max_object`, `remove_max_object`, `connect_max_objects`, `disconnect_max_objects`, `set_object_attribute`, `set_message_text`, `send_bang_to_object`, `send_messages_to_object`, `set_number`). Read-only inspection tools (`list_all_objects`, `get_object_doc`, `get_objects_in_patch`, `get_objects_in_selected`, `get_object_attributes`, `get_avoid_rect_position`) are fine without confirmation. Reason: patch edits hit live performance state and are easy to desync from `xk_swam.js` / `gen_includes.js`; a skipped prompt has bitten us before.

Prerequisite: open `MaxMSP-MCP-Server/MaxMSP_Agent/demo.maxpat` in Max 9+, `script npm install` (first time), then `script start`.

**Boundary**: keep the XenaKube patch thin — the chain shown above plus optional `[print xk_swam]`. All new routing/logic belongs in `max/xk_swam.js`, not in new Max objects.
