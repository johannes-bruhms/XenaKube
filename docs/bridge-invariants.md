# Bridge Invariants — Full Enforcement Detail

> CLAUDE.md keeps a compressed summary of each invariant (claim + where + failure log). This file is the source of truth for *how* each invariant is enforced and *what* the failure logs surface. Read this file before changing any code that touches an invariant.

SWAM Cello is a stateful physical-modeling VST. Several features (portamento, harmonics, tremolo, bow polyphony, expression envelope) depend on the plugin being in a specific internal mode that no MIDI wire inspection can confirm. These are silent-failure surfaces: you can emit "correct-looking" MIDI and get no slide, no harmonic, no tremolo. Every such feature must be paired with a runtime invariant that fails loudly.

**Hard rule for modulators** (face envelope, intensity map, regime multipliers, path scalars, voice-stealing, any future feature that touches voice dispatch): they may *reshape* a complex's gesture (duration, velocity, density, register, contour) but MUST NOT *eliminate* the structure that defines the complex's identity. Face `isSingle` collapsing C5/C6/C7 to zero gliss steps was the exact mistake D42 fixed — don't repeat the pattern with any other complex/mode combination.

When you add a new modulator that intersects an existing invariant, re-audit every invariant in the list below. "Assumed preserved" is how regressions happen.

| **Gliss event count** (D42 + D46 + D59) — every C5/C6/C7 voice emits ≥1 `glissStep` call. `glissStep` classifies the transition as a legacy same-string portamento slide (`glissNote`), pitchbend slide (`bendStep`), or over-range/string-crossing fallback (`leapStep`) and tallies into `glissOverlapCount` / `glissBendCount` / `glissLeapCount`. Invariant is `slides + bends + leaps ≥ 1`, not `slides ≥ 1`. | `max/xk_swam.js` `glissStep` (dispatch) + `sameString` + `CELLO_STRINGS` table (string ranges) + `phraseC5` / `phraseC6` / `phraseC7` (route every gliss pitch through `glissStep`). | Structural: phrases call `glissStep` directly. `faceShapedCount(forGliss=true)` minimum is 1, not 0. `phraseC6` forces `count ≥ 2`. `phraseC7` always fires ≥1 drift regardless of `isSingle`. | Always-on per-phrase log line: `inst N CX face=F slides=S bends=B leaps=L dur=D` from `scheduleRelease`'s natural-end task. Promotes to `GLISS FAIL ... slides=0 bends=0 leaps=0 ...` if all three are 0. Stolen phrases clear `glissExpected` in `stealInstance` to avoid false positives. The slide/bend/leap breakdown lets the user audit gliss distribution per face/intensity in real time. |
| **Immediate first gliss** (D43 + D53) — the first `glissStep` of every C5/C6/C7 voice fires at a per-complex first-gliss time from phrase start, independent of duration. C5/C6 use `FIRST_GLISS_MS = 150` ms (anchor establishes a clear starting pitch before the slide). C7 uses `FIRST_GLISS_MS_C7 = 30` ms (D53 — anchor barely audible, drift starts almost immediately so C7's "wispy ephemeral wandering" character reads as continuous floating rather than C6's deliberate stepping). A stolen-short voice (fast turn at ~300 ms) still delivers an audible slide instead of playing as a sustained single note. | `max/xk_swam.js` `FIRST_GLISS_MS` and `FIRST_GLISS_MS_C7` constants; `phraseC5` / `phraseC6` / `phraseC7` schedulers | Structural: phrases schedule idx 0 (C5, C7) or idx 1 (C6) at the per-complex first-gliss time as a hard constant; remaining slides distribute through the phrase tail. `scheduleRelease`'s 200 ms floor is always > both first-gliss times, so the first slide never races the release ramp even at tiny durations. C7's 30 ms is also large enough that the noteon→scheduled-noteoff window remains GLISS_OVERLAP_MS = 60 ms (the overlap is the schedule, not the gap between the two noteons). | No dedicated failure log — the D42 "GLISS FAIL overlaps=0" counter catches any regression that would affect this too. Slide latency is a tunable, not an invariant. |
| **Turn-to-noteon latency telemetry** — every `/xk/voice` emitted by the engine should produce a first non-companion `/xk/midi/noteon` echo quickly enough for live play. This probe measures relay→Max bridge timing only: timestamp at `engine.onVoice`, then timestamp the first non-companion MIDI noteon echo returning over UDP 57122. It does **not** measure SWAM acoustic attack, `Auto Poly Detect Time`, host audio-buffer latency, or slow CC 11 ramps that can make a timely note feel late. Those must be diagnosed after the bridge echo budget is proven. | `relay.js` `startVoiceLatencyProbe(output)` runs before sending OSC to Max; `completeVoiceLatencyProbe(data)` consumes the oldest pending probe on first non-companion `OSC.MIDI_NOTEON`; `expireVoiceLatencyProbes(now)` fails probes with no echo. Per-complex rolling windows are kept in `latencyByComplex`. | Structural: one pending probe per `engine.onVoice` output. Companion noteons are ignored so C5/C6 double-stop companions cannot satisfy the first-onset probe. Pending probes are capped and expired so a missing Max echo cannot poison later measurements indefinitely. | `[LATENCY WARN] turn->noteon ...` at `LATENCY_WARN_MS = 150`; `[LATENCY FAIL] ...` at `LATENCY_FAIL_MS = 250`; `[LATENCY FAIL] no noteon echo within 3000ms ...` if Max never echoes a noteon. Each warn/fail includes per-complex rolling `n`, `p50`, `p95`, and `max`; every eighth normal sample logs the same summary. |
| **Immediate expression seed** — non-arc phrase envelopes must not make the first note wait for CC 11 to climb from zero. Before this invariant, `scheduleExprEnvelope` ramped from the prior value to the attack value over `max(baseAttack, min(durMs * 0.10, 800))`; with 2-5 s vertex durations that produced 200-500 ms of quiet onset, and with face duration bias it could hit the 800 ms cap. That sounded exactly like per-face latency or dropped notes even though MIDI noteon was timely. | `max/xk_swam.js` `scheduleExprEnvelope` now `ccForce`s `peakExpr * env.attack` synchronously before phrase dispatch, then schedules the later peak/sustain ramps. Phrase arcs and hairpins already seeded their start value synchronously via `schedulePhraseArc` / `schedulePhraseHairpin`. Relay tracks latest `/xk/midi/expr` echo per voice and annotates the first-noteon latency log with `expr=V exprAge=Nms`. | Structural: the attack CC write happens before the phrase generator switch in `handleVoice`, so every immediate `noteOn` / `legatoNote` sees an already-seeded CC 11. The later peak/sustain timing remains phrase-shaped; only the silent attack ramp from zero is removed. | `[ONSET EXPR WARN] first noteon arrived quickly but CC11 is low ...` when bridge noteon latency is under the warn threshold but the latest expression echo for that voice is below 32. This is diagnostic, not a hard failure: very soft K-dynamics can be intentionally below 32, but the log separates "MIDI was late" from "MIDI was on time but acoustic energy was low." |
| **Face-owned duration** (D74) - each face-triggered voice resolves phrase duration from `FACE_MAP.durationSec`, not from K_i vertex duration. This preserves the performer forward model: face chooses gesture time, K_i modulates density/intensity only. | `src/face-gesture.ts` `durationSec`; `src/vertices.ts` neutral `duration=1`; generated `max/gen_includes.js`; `max/xk_swam.js` `handleFace` / `handleVoice`; `src/osc-output.ts` sends `/xk/face -` on null faces to prevent stale-face bleed. | Structural: normal face turns set `state.faceDurationSec` from generated FACE_MAP; `handleVoice` uses it absolutely and only falls back to incoming vertex duration when no face is pending. | `FACE DURATION FAIL face=F ...` if FACE_MAP lacks `durationSec`; normal voice logs include `dur=Ns(face)`. |
| **Min gliss spacing** (D45) — consecutive `glissStep` events on a single phrase are never closer than `MIN_GLISS_SPACING_MS` (200 ms). Current C5/C6/C7 normally route through `bendStep`, so the floor gives each pitchbend ramp and atomic noteoff/noteon transition room to complete before the next target. Legacy `glissNote` portamento fallback also needs roughly this much time to engage. Phrases that can't fit their requested count at this spacing get `count` clipped to whatever fits. | `max/xk_swam.js` `MIN_GLISS_SPACING_MS` constant; `glissSchedule` helper used by `phraseC5` / `phraseC6` / `phraseC7` | Structural: every gliss complex routes its event timing through `glissSchedule(maxCount, firstMs, tailEnd, MIN_GLISS_SPACING_MS)` which enforces the floor and truncates count if events would run past `tailEnd`. | No dedicated failure log — same shared D42 "GLISS FAIL" catches anything that breaks gliss entirely. Spacing is a tunable; if SWAM/Max scheduling behaviour changes, raise/lower `MIN_GLISS_SPACING_MS`. |
| **Leap-alternation with per-complex tolerance** (D48 + D58) — leaps (cross-string `leapStep`) are capped per gliss complex via `MAX_LEAPS_BY_COMPLEX = { 5: 1, 6: 0, 7: 0 }`. Once a complex's count is reached, the next would-be cross-string outcome is nudged onto source's strings to force a slide. **C5 (wild gliss)** keeps `maxLeaps = 1`: occasional cross-string punch is part of the wild character; `phraseC5` seeds `inst.consecutiveLeapCurrent = MAX_CONSECUTIVE_LEAPS` at phrase start so the first event is forced to slide ("wild gliss must always begin with a slide"). **C6 (ord. gliss)** and **C7 (tasto)** use `maxLeaps = 0`: every cross-string outcome is nudged to same-string. **Now mostly inert** because D59 (cross-string pitchbend slides) routes most cross-string outcomes within `PITCHBEND_RANGE_SEMI = 48` to `bendStep` (counts as a slide for the leap counter); the per-complex max only fires for over-range intervals (rare). Table preserved as a belt-and-suspenders fallback if pitchbend is ever disabled (e.g. SWAM preset reset to ±2). | `max/xk_swam.js` `MAX_LEAPS_BY_COMPLEX` table + `maxLeapsFor(complexType)` helper; `glissStep` (counter-gated nudge using per-complex max) + `nudgeToSameString(sourcePitch, preferTarget, minLeap)` (picks a same-string target ≥ minLeap from source; candidate strings shuffled when source sits in a multi-string overlap zone so trajectory isn't biased toward one string) + `phraseC5` seeds `inst.consecutiveLeapCurrent = MAX_CONSECUTIVE_LEAPS` for the forced-slide opening; `handleVoice` zeros `consecutiveLeap*` counters generically. Per-complex max is the single tunable; raise C5 to 2 if the wild punch feels too tame, or set every entry to 0 to eliminate cross-string leaps entirely. | Structural: `glissStep` checks `(inst.consecutiveLeapCurrent | 0) >= maxLeapsFor(inst.activeComplex) && !sameString(...)` and nudges target to same-string before dispatch. `nudgeToSameString` returns null only when source is at the extreme of every string it sits on with no minLeap headroom in either direction (rare — extreme cello-range corners). | Per-phrase log in `scheduleRelease` natural-end task tracks `inst.consecutiveLeapMax`. `consecutiveLeapMax > maxLeapsFor(inst.activeComplex)` (run exceeded per-complex tolerance despite the nudge) promotes to `GLISS RUN FAIL inst N CX face=F slides=S leaps=L consecLeapMax=M (max for CX = M_max) dur=D`. Otherwise the existing per-phrase `slides=S leaps=L` line is unchanged. For C6/C7 (max=0) ANY leap trips the FAIL — should be rare-to-never; a hit indicates a `nudgeToSameString` corner failure or a regression. |
| **Selector re-assertion** (D44 + D69) — CC 78 (Harmonics) / CC 79 (Tremolo) / CC 81 (Bow Polyphony) are written by `setHarmonics` / `setTremolo` / `setBowPolyphony` regardless of cached state, and CC 81 is additionally re-asserted in `handleVoice` per `/xk/voice` event. Selectors can desync between the bridge and SWAM (preset reload races, MIDI Learn glitches, voice steal during plugin re-init). Diff guards that "skip the same value" silently freeze the plugin in the wrong mode — D44 was Mono Poly Release stuck on (killing double stops); D69 was tremolo stuck on at startup (every C1–C7 phrase tremolo'd until the first C8 broke the cache `OFF→FAST→OFF`). The race is identical in both cases: `resetInstance` writes its CC before SWAM's preset finishes loading, so the bridge cache reads "off" while SWAM lands on whatever the preset / `vst~` default is, and every later same-value call returns early through the diff guard. `setHarmonics` got the same fix prophylactically — the C4-only callsite hadn't been reported broken yet, but it carries the same race. | `max/xk_swam.js` `setHarmonics` / `setTremolo` / `setBowPolyphony` (no diff guard) + `handleVoice` per-voice CC 81 re-assert. `setupComplex` calls all three on every complex switch. | Structural: each function always writes its CC; `handleVoice` writes CC 81 again per voice using `cmx.bowPoly` from the COMPLEX table. | `log("inst N harmonics=H cc78=V")` / `log("inst N tremolo=T cc79=V")` / `log("inst N bowPoly=B cc81=V")` on every selector write — read the Max console to verify the bridge is asserting the expected mode for each complex. The D44 setBowPolyphony comment block in `xk_swam.js` is the canonical race description; the D69 setTremolo block is the same race observed on a second selector. |
| **Phrase dynamic arc** (D47, D57) — sustained-and-gliss multi-note complexes (C2/C3/C4/C5/C6/C7/C8) emit a single linear CC 11 ramp across the full phrase duration: cresc TO `inst.peakExpr × ARC_CEIL` for swell faces (L/F/F'), dim FROM `inst.peakExpr × ARC_CEIL` to `× ARC_FLOOR` for fade/burst faces (U'/L'/R'). Hairpin faces (D' = `<>` hairpin-up, B' = `><` hairpin-down) route to `schedulePhraseHairpin` instead — start → mid → start trajectory over `durMs/2` + `durMs/2` halves. **C1 pizz (D57)** uses static `ccForce(CC.EXPRESSION, peakExpr)` at phrase start with NO envelope — per-pluck velocity is the dynamic that audibly belongs to pizz. isSingle face envelopes (pluck/stab/hairpin-up/hairpin-down) on non-pizz complexes resolve to one note; pluck/stab fall through to `scheduleExprEnvelope`, which now seeds attack synchronously and only ramps later peak/sustain stages. **Chaining** (cresc/dim only, not hairpin which is symmetric/self-contained): consecutive same-direction voices arriving within `ARC_CHAIN_GAP_MS = 1000` ms of the previous arc's exit (natural-end OR steal) CHAIN — the new arc inherits `ccCache[CC.EXPRESSION]` (no ccForce snap) so a long swell across multiple cube turns reads as one continuous dynamic. Direction mismatch / timeout / first arc breaks the chain cleanly. | `max/xk_swam.js` `ARC_FLOOR` / `ARC_CEIL` / `ARC_COMPLEXES = {2,3,4,5,6,7,8}` / `ARC_CHAIN_GAP_MS` constants; `phraseArcDirection(inst)` (face envelope → 'cresc'/'dim'/'hairpin-up'/'hairpin-down'/null) + `schedulePhraseArc(inst, peakExpr, dir, durMs)` (cresc/dim, with chain check via `inst.lastArcDir/lastArcEndTime`; ccForce snap only when chain breaks; single rampCC) + `schedulePhraseHairpin(inst, peakExpr, dir, durMs)` (hairpin-up/down, two rampCC halves with mid peak/trough at `durMs/2`); dispatch in `handleVoice` selects arc vs hairpin vs `scheduleExprEnvelope` per `(complexType, faceEnvelope)`. Voice steal AND natural-end refresh `inst.lastArc*` so subsequent voices can chain off either termination. | Schedule-time `inst N phraseArc dir=cresc face=swell start=38 end=127 dur=2500ms` log confirms direction landed before play; appended `[chained gap=420ms]` when chain fired. Hairpin emits `inst N phraseHairpin dir=hairpin-up face=hairpin-up start=38 mid=127 end=38 dur=2500ms`. Natural-end assertion in `scheduleRelease`: `ccCache[CC.EXPRESSION]` should equal `phraseArcEnd` ±8 of 127 (~6%); promotes to `ARC FAIL inst N CX face=F dir=D landed=L want=W off=O dur=D` on miss. For hairpin, `phraseArcEnd === phraseArcStart` (returns to start) so the fade picks up at low (hairpin-up) or high (hairpin-down) — the latter has the longer audible release, an intentional asymmetry. Hits emit `inst N CX arc=cresc 38->127 dur=2.50` for direction audit. Chain candidacy is refreshed in BOTH `scheduleRelease`'s natural-end task AND `cancelPhrase` (steal path) so a stolen mid-arc voice still seeds a chain candidate for the next voice. |
| **Bow-position smoothness** (D54) — `handleExprTilt` writes CC 16 (Bow Position) at 30 Hz from gyro tilt, EMA-smoothed to match the `spinEMA` / `devEMA` convention. Without smoothing, gyro static-pose noise (~0.005 in normalised tilt) amplified through `(val − 0.5) × 60` and `Math.round()` flickers between two adjacent CC integers — SWAM hears that as a 30 Hz bow-position wobble (sub-vibrato bow buzz on sustained voices). | `max/xk_swam.js` `state.tiltEMA` (initialised at rest pose 0.5); `TILT_EMA_ALPHA = 0.05` constant (smaller than `spinEMA`'s 0.08 because tilt is always-emitting with no deadband; τ ≈ 670 ms absorbs static noise without lagging intentional tilts); `handleExprTilt` updates `tiltEMA` and computes jitter from it (not raw `val`). Per-instance `bowPosWrites` / `bowPosReversals` / `bowPosLastDir` counters track CC 16 emit pattern within a voice. | Per-phrase log `inst N bowPosFlap rev=R writes=W rate=R/s` always emits when CC 16 fired during the voice; promotes to `BOW POS FLAP inst N CX reversals=R writes=W dur=D (rate=R/s, fail>BOW_FLAP_RATE_FAIL)` when reversals/sec exceeds `BOW_FLAP_RATE_FAIL = 10`. Counters reset in `handleVoice` and `bang`'s reset block. The threshold tolerates active tilting (~5–10 reversals/sec is legitimate user gesture); flap regression returns 30+ reversals/sec on a held cube. |
| **Portamento state at slide** (D55, diagnostic) — every `glissNote` invocation (the slide noteOn for same-string gliss steps) MUST be backed by SWAM having `CC 5 (PORTAMENTO_TIME) = cmx.portamento.time`, `CC 64 (PORTAMENTO_ON) = 127`, and (if `HAS_BOW_POLY_CC`) `CC 81 (BOW_POLYPHONY) = BOW_POLY_CC_VAL[cmx.bowPoly]`. The "wiggle through 0" trick in `setupComplex` / `handleVoice` (CC 5 = 0 → CC 5 = time, forcing SWAM v3 to register a parameter-change event) can race a noteOn if the two writes straddle a MIDI buffer boundary; SWAM ends up latched at 0 → instant glide → no audible slide while the bridge still emits noteon-overlap and the dashboard draws as gliss. Diagnostic-only for now; logs identify whether bridge `ccCache` agrees with intent. NOT a fix for SWAM↔bridge wire drift (would need a `vst~ pattr` read-back, deferred). | `max/xk_swam.js` `glissNote` entry-time assertion. Reads `inst.ccCache[CC.PORTAMENTO_TIME]`, `inst.ccCache[CC.PORTAMENTO_ON]`, `inst.ccCache[CC.BOW_POLYPHONY]` against `cmx.portamento.{on,time}` + `BOW_POLY_CC_VAL[cmx.bowPoly]`. | `PORT TIME FAIL inst N CX pitch=P wantTime=W gotTime=G gotOn=O polyOk=B` on any mismatch. If this fires under load, the next fix is the wiggle-without-zero pattern: write `time + 1` then `time` so a racing noteOn at worst sees a 1-unit-slower slide (graceful degradation), never silent failure. Always-on; cost is one cache lookup per slide noteOn. |
| **Cross-string slide via pitchbend** (D59 + D72) — `glissStep` three-way dispatch routes every gliss step into one of three paths based on `(interval, sameString, cmx.slideViaBend)`: (1) `|interval| > PITCHBEND_RANGE_SEMI` → `leapStep` (with `BEND CLIP` log; over-range fallback). (2) `|interval| ≤ PITCHBEND_RANGE_SEMI` AND (`cmx.slideViaBend === true` OR `!sameString(src, dst)`) → `bendStep` (pitchbend wheel ramp on the held source, then atomic `bend=0 + noteOff(source) + noteOn(target)` at ramp end). (3) Otherwise → `glissNote` (legacy same-string portamento fallback). Current `COMPLEX[5]`, `[6]`, and `[7]` all set `slideViaBend = true`, so normal gliss steps route through `bendStep` and can scale each slide to the gap-to-next-event, bypassing the CC 5 ≤ 127 ms/semi portamento cap. Bend source must be looked up in `inst.activeNotes`, NOT re-derived via `humanPitch` (which has a 10%-chance ±1 semi shift; re-call would mismatch noteOff). When `desiredDurMs` is null, bend duration falls back to `_bendDur(from, to, complex)` clamped to `MIN_GLISS_SPACING_MS - BEND_DUR_MARGIN_MS = 195 ms` for D60 race-safety. | `max/xk_swam.js` `bendStep(inst, src, dst, vel, accent, complex, desiredDurMs)` finds `heldSource` via `Math.round`-tolerant lookup in `inst.activeNotes`; `emitPitchbend` / `rampPitchbend` (5 ms tick) / `cancelPitchbendRamp` helpers; `inst.pitchbend` / `inst.pitchbendRampTasks` / `inst.bendPending` / `inst.bendPendingTask` instance state. `completeBend(inst, scheduled)` is the single execution path for the atomic ramp-end transition — called either from the scheduled task at `t+durMs` OR force-inline from `glissStep` entry when `inst.bendPending` is set (race-safety against scheduling jitter < 5 ms). `glissStep(inst, src, dst, minLeap, vel, accent, bendDurOverride)` forwards `bendDurOverride` to `bendStep` as `desiredDurMs`. `phraseC5`, `phraseC6`, and `phraseC7` compute per-slide/per-drift `bendDur = clamp(gapMs - 50, 80, MAX_BEND_DUR_MS)` from the time to the next event or phrase end. `cancelPhrase` + `bang` reset pitchbend to `PITCHBEND_CENTER = 8192` AND clear `bendPending` so a stolen mid-bend voice can't ghost-fire its transition after `allNotesOff`. | Per-phrase log: `inst N CX face=F slides=S bends=B leaps=L dur=D`. D42 `GLISS FAIL` invariant: `slides + bends + leaps < 1` triggers fail. Current C5/C6/C7 normally log `bends=N`; `slides` is for legacy `glissNote` fallback. `BEND CLIP` logs when an over-range interval falls back to `leapStep`. `BEND FAIL` logs when `bendStep` is asked to bend a pitch not in `inst.activeNotes` (defensive fall-through to `leapStep`). `bend race-fix` logs when `completeBend` runs inline before its scheduled task, indicating scheduling jitter exceeded the 5 ms margin. Dashboard: `/xk/midi/bendstep` OSC echo flows through relay → WS `midi_echo` (kind=`bendstep`) → `triangle.bendStep` + `rolling-score.bendStep`. |
| **Pitchbend range bridge↔preset alignment** (D64) — `max/xk_swam.js` `PITCHBEND_RANGE_SEMI` MUST EXACTLY MATCH the SWAM preset's Master Tuning → Pitchbend Range setting (saved in `xenakube_2.swam` / current preset). MIDI pitchbend is a 14-bit wheel position with NO semitone information; SWAM does the conversion using its preset value. Mismatch silently produces audible-bend ≠ visual-bend: bridge sends value14 expecting one scale, SWAM applies another, audible bend is over- or under-strength by the ratio. Severe mismatches (preset reverted to default ±2 vs bridge at ±48) are 24× weaker than intended → audible bend barely moves, then the `noteOff(source) + noteOn(target)` at end of bend fires the discrete jump audibly → "leaping" perception even when the bridge is bending correctly. **Breaks silently any time the SWAM preset changes without a paired bridge re-sync.** | Manual sync of the bridge constant against the preset's UI value. `PITCHBEND_RANGE_SEMI` is a paired tunable — change one, change the other. | `bang()` logs `=== BRIDGE PITCHBEND_RANGE_SEMI = ±N — verify this matches SWAM preset's Pitchbend Range ===` on every Max v8 reload. Visible in `[print xk_swam]`. Cross-check against the SWAM preset's actual Pitchbend Range setting every reload. If they ever disagree, the bridge constant must be updated and the v8 reloaded. (Runtime auto-detection would require a `vst~ pattr` read-back — deferred; the loud reminder is the practical guard.) |
