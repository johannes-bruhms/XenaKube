# Dashboard Architecture

> The browser-side dashboard's structure: module layout, cross-module read surfaces, overlay positioning, and rolling-score brush rendering. CLAUDE.md keeps a one-paragraph summary; this file is the deep reference. Read alongside `docs/dashboard-invariants.md` (visual-side runtime invariants) when changing any module under `public/`.

## Entry point

`dashboard.html` at `http://localhost:3000`. Full-viewport HUD: `#cube-canvas` fills the window; all UI floats as transparent overlays. Three.js 3D cube with per-vertex K#/D/G/U labels, a ghost C-cube that snap-rotates from `state.snapQuat`, top-face slot markers, adaptive live/ghost wireframes on `#cube-contrast-layer`, through-cube-visible signature decals that show two unlabeled underlined marks per face, twist transiently in their face plane on turns, then snap back upright, and C identity dots that are fixed to local slots in beta-cosmo but walk across slots in alpha-cosmo. C dot color and texture are locked to the MIDI brush palette; vertex labels draw their own tight semi-opaque panels. On phrase triggers, the active K/C labels are pulled together and fade into the floating K/C cards while the active live and ghost dots elastically attract without fully sticking; the card cluster itself anchors to the active ghost C projection so live gyro motion does not drag it around. WS client to relay. Pixel/zoom values live in CSS (L48-60).

## Module layout (Phase 2 complete)

- `dashboard.html` — HTML structure only. Single `<script type="module" src="./js/main.js">` mounts the entry. The pre-Phase-2 monolithic version is preserved at `dashboard.v1-monolith.html` (also served by the relay; reachable at `:3000/dashboard.v1-monolith.html`) for direct A/B comparison.
- `css/main.css` (Phase 2.2) — all dashboard styles, sectioned by overlay. CSS variables `--roll-top-inset` / `--roll-bottom-inset` MUST equal JS `ROLL_TOP_INSET_PX` / `ROLL_BOTTOM_INSET_PX` (rolling-score's `assertPitchAxis` fires loudly on drift).
- `js/constants.js` (Phase 2.1) — shared immutable constants (`ROLL_*` insets / pitch range / brush scale, `GLISS_GAP_MS` / `GLISS_COMPLEXES`, `PORTAMENTO_MS_PER_SEMITONE` / `GLISS_PORTAMENTO_MS_PER_SEMITONE` mirrors of the bridge, `COMPLEX_COLOR` palette plus the sRGB `COMPLEX_COLOR_SRGB_HEX` material mirror, `PIZZ_FADE_MIN/MAX_MS`, `PENDING_MAX_AGE_MS`).
- `js/transport.js` (Phase 2.3) — WebSocket transport. `connect()` / `send(obj)` / `isOpen()` / `on(name, fn)`. Auto-reconnect at 2 s while the page is live; `pagehide` / `beforeunload` closes the socket and suppresses reconnect so the relay can shut down immediately when the last dashboard is gone. Typed events include state/gyro, algorithms, phrase audit, `midiEcho`, `spectrumFrame`, and `spectrumStatus`. Outbound browser `gyro` mirrors are dropped under WS `bufferedAmount` pressure; live `move` messages are still attempted.
- `js/sieve.js` (Phase 2.4) — 49-cell pitch strip + per-cell emanation glow + active-set highlighting. Owns `assertSieveLayout` (init-time invariant). Exports `noteOn` / `noteOff` / `panic` / `setActive` / `getCellRect(pitch)` / `SIEVE_RANGE` / `BLACK_KEYS`.
- `js/cube-scene.js` (Phase 2.5) — Three.js scene: live K-cube, snap-tracking ghost C-cube, K↔C 3D line, top-face slot markers, adaptive contrast wireframe pass, through-cube-visible signature decals, gizmo, all per-frame animations (gyro live rotation, ghost snap SLERP, face-glyph turn cue, active-step LERP, K-vertex LERPs, active highlights, active-pair elastic attraction, active-label merge/fade), camera auto-fit, gyro zero. The glyph side-ring is display-remapped so the current L-position decal carries F while U/D stay fixed; face-turn state stays keyed to the actual mesh face so an `F` move still twists the real `F` face. Each turn twists the decal only as a transient motion cue, then snaps it back to canonical upright orientation; the U and D face decal bottoms point toward F/user. Each decal is a DoubleSide transparent plane with two unlabeled underlined move marks, so viewing through the cube uses the natural back view instead of camera-side flip compensation. Ghost orientation uses `state.snapQuat`, not phrase-lockable `state.cQuat`; C identity meshes and labels stay fixed to local slots in beta-cosmo, but walk to the assigned slot from `state.cAssignments` in alpha-cosmo. C identity mesh colors and procedural dot textures come from the MIDI brush palette and ignore old saved C vertex colors. In beta-cosmo the active ghost ring resolves from the active local slot, matching the fixed C label in that corner, while alpha-cosmo can still highlight the assigned C type. Exports `init({ onAutoZero })` / `setCubeQuat([x,y,z,w])` / `update(state)` / `applyConnectView()` / `revertConnectView()` / `zeroGyro()` / `setGhostScale(s)` / `setAppearance(settings)` / `resetAppearance()` / `getAppearance()` / `getActiveKWorldPos(out)` / `getCWorldPos(c, out)` / `getActiveCardAnchorScreenPos(out)` / `getCamera()`. Owns the rotate-target buttons (cam/live/ghost), ghost-size slider geometry, ghost-anchored active-card projection with left/right side hint, and cube-color-panel appearance targets.
- `js/rolling-score.js` (Phase 2.6) — full-viewport MIDI brush piano-roll canvas + per-complex procedural brushes + gliss-chain Path2D stroker + slide-vs-leap chainStart classifier (rolling-side) + Phase 1 invariants (`assertPitchAxis` per resize, `assertGlissSync` ~1 Hz when a gliss line is active) + stuck-note watchdog. Exports `init({ onForceFinalise, getActiveGlissLineDisplay })` / `noteOn` / `noteOff` / `panic` / `setScrollSpeed` / `setVisible` / `setVisualDelay` / `getCanvas` / `hasActiveNote(voice, complex)`.
- `js/spectrum-score.js` — optional actual-audio spectrogram canvas behind the MIDI brush layer. Consumes only `spectrumFrame` WS data from Max, buffers frames by audio timestamp, applies shared visual latency/nudge, switches declarative color modalities by the frame complex (relay-filled from latest audio-side MIDI noteon when Max sends `complex=0`), clears visible history when timing/look/palette settings would reinterpret old pixels, and warns on missing/stale/out-of-order frames. Stale frames scroll existing history but do not paint new spectrum columns. Exports `init` / `setEnabled` / `setScrollSpeed` / `setTiming` / `updateState` / `handleFrame` / `getCanvas` plus look and modality-palette setters.
- `js/performance-recorder.js` — optional long-PNG recorder. Samples the right-edge columns of visible/composite/spectrum/MIDI rolling visual layers into an offscreen print buffer, then saves a PNG on end.
- `js/triangle.js` (Phase 2.7) — K↔sieve / C↔sieve leg overlay, defaulting to white but runtime-tunable from the cube colors panel. Cubic-smoothstep slide easing matches rolling-score exactly (Visual Invariant #3). Exports `init({ getCamera, getActiveKWorldPos, getCWorldPos, getSieveCellRect, hasActiveGliss })` / `setAppearance(settings)` / `resetAppearance()` / `getAppearance()` / `noteOn` / `noteOff` / `panic` / `getActiveGlissLineDisplay(now)`.
- `js/state-ui.js` (Phase 2.8) — overlay panels: state rows, mode badges, floating K/C cards, perm slots, algorithm buffer + toast, scramble bar, expression panel, recent-moves FIFO. Reads `FACE_SIG` and `paintFaceGlyph` from `js/face-glyph.js` for the text face row and active-card glyph, and mirrors cube-scene label appearance through `setAppearance(settings)` so K/C card text follows the same K, C, active, and detail label colors. Owns `COMPLEX_SHORT`. Exports `init({ getActiveCardAnchorScreenPos })` / `setAppearance(settings)` / `update(state, move)` / `setCosmologyBadge(cosmology)` / `handleAlgorithmEvent` / `setSolvedBadge(solved, pulse)` / `updateExpression(quat, dev)` / `setAlgorithmBook`.
- `js/main.js` (Phase 2.9) — entry point. Imports every module, calls each one's `init()`, wires cross-module callbacks including the state-ui active-pair card anchor, mirrors cube-scene label appearance into state-ui cards, subscribes transport events to module update entry points, wires sliders + buttons + the visible alpha/beta cosmology toggle (`set_mode.cosmology`) + rolling layer toggles + spectrogram settings panel + cube colors panel + dashboard presets panel + Web Bluetooth GAN cube connection, blocks BLE connect until the relay WS is open, invalidates an active cube session if that socket closes, unit-normalizes GAN gyro events, keeps relay `gyro_tick` as the live-cube pose writer, coalesces outbound gyro to latest-only relay sends with pre-move/pre-zero flushes and a move-inline fallback, requests cube bootstrap facelets after connect, owns the raw GAN `U'`×4 zero-gyro shortcut, dispatches `midi_echo` to sieve + triangle + rolling-score in one place, and forwards spectrum frames only to `spectrum-score`.
- `js/settings-sync.js` — portable dashboard persistence. Owns the localStorage key allowlist, active settings push to `data/dashboard-settings.json` via `/api/dashboard-settings`, and named preset helpers for `data/dashboard-presets.json` via `/api/dashboard-presets`. The synchronous bootstrap allowlist in `dashboard.html` must match `SYNCED_KEYS` exactly.
- `interruption/` — optional performance overlay package, disabled unless the URL includes `?intrusions=1` or the debug `I` key enables it. `index.js` owns the pressure state machine, generated/video playback, targeting canvas, debug keys, injected CSS, and DOM cleanup. `config.js` owns first-draft pressure/duration tunables. `clips.js` owns local clip metadata and generated placeholder entries. `main.js` is the only import and fanout boundary.

## Cross-module read surfaces (intentional, narrow — see `docs/todo.md` Phase 2 ownership table)

- `triangle` reads cube-scene `getActiveKWorldPos` / `getCWorldPos` / `getCamera`, sieve `getCellRect`, rolling-score `hasActiveNote`.
- `rolling-score` reads triangle `getActiveGlissLineDisplay` (wired via init() callback to avoid circular import) so `assertGlissSync` can compare line ↔ chain trajectories.
- `state-ui` reads cube-scene `getActiveCardAnchorScreenPos` (wired via init() callback) so phrase-triggered K/C cards sit by the active ghost C projection, not the live cube. The callback also returns a side hint based on the ghost vertex relative to the ghost cube center; `state-ui` places cards inward so left-side vertices open right and right-side vertices open left.
- `interruption` reads cube-scene `getCamera` / `getActiveKWorldPos` / `getCWorldPos` through `main.js` only, for its separate targeting canvas. If those callbacks are absent while the module is enabled, it warns once and leaves target projection disabled.

The "Cross-module init wiring" Dashboard Visual Invariant (`docs/dashboard-invariants.md`) covers the runtime contract that protects these surfaces.

## Overlays

- **Top-left** (`.ovl-tl`): title + MAC/connect (button turns green via `.connected`), alpha/beta cosmology toggle, mode badges.
- **Bottom-left** (`.ovl-bl`, anchored `bottom: 110px`): State panel (face, active voice, S4 element, path, step, snap, complex phase, orbit, scramble, permutation), then Expression panel (Zero Gyro + smoothing slider + tilt/spin/deviation/scramble). The physical raw GAN `U'`×4 shortcut mirrors the Zero Gyro button and must not depend on calibrated `state.upFace`. `zoom: 0.5` applies per-child to keep the bottom anchor zoom-invariant so the stack never overlaps the sieve strip.
- **Top-center** (`.ovl-tc`): cube-algorithm buffer + algorithm notification. Move strip is a dashboard-side 8-move FIFO (`recentMoves`, `RECENT_MOVES_MAX = 8`), decoupled from the engine's `state.algorithmBuffer` (which clears on its own 2 s timeout / algorithm-fire); each turn pushes one move and shifts the oldest, so the strip never empty-flashes. Match-highlighting still consumes `state.algorithmPartials` and applies to the trailing N entries.
- **Top-right**: cam / live / ghost rotate toggles + rotation gizmo.
- **Bottom**: full-width sieve piano-roll (C2–C6).
- **Background visual layers** (`#rolling-score` z-index -1, `#spectrogram-score` z-index -2): MIDI brushes draw above the optional actual-audio spectrogram. Both layers are independently toggleable from the bottom-right `layers` row; default is MIDI on, spectrogram off. A `spectrogram settings` button in the same bottom-right cluster opens the tuning panel for visual delay, audio/MIDI nudge, global gain/floor/ceiling setters, background brightness, shared background and ceiling colors applied to every named and modality palette, interpolation density, canvas blur, temporal smoothing, palette override, per-modality gain/floor/ceiling, and interior C1-C8 modality palette stops. Modality comes from the spectrum frame's complex; relay fills unknown frame complex from audio-side MIDI noteon timing rather than engine-state timing. Nudge changes clear buffered spectrum metadata because the audio-time mapping changes; look and palette changes clear visible spectrum history so old columns are not mixed with a new interpretation. Right edge = visual now, scrolling left at `ROLL_PX_PER_SEC` CSS-px/sec (default 360, retunable live via the `score` slider). Pitch/frequency axis uses `ROLL_TOP_INSET_PX = 70` / `ROLL_BOTTOM_INSET_PX = 80`.
- **Cube colors panel** (`#cubeColorsPanel`): bottom-right toggleable panel parallel to spectrogram settings. It persists K vertex colors, label color/follow-vertex behavior, active/detail label colors, live/ghost/K-C/tetra/adaptive wire colors, top markers, active halos, effective adaptive wire widths, and triangle K/C/sieve leg colors, width, endpoint dot size, and opacity. C vertex colors are not editable; their color and dot texture are locked to the MIDI brush palette. Label appearance also feeds `state-ui.js` so the merged K/C card text follows the same K, C, active, and detail controls. The panel writes only through `cube-scene.js` / `triangle.js` appearance setters; geometry, snap state, and MIDI line lifetimes remain owned by their original modules.
- **Dashboard presets panel** (`#dashboardPresetsPanel`): bottom-right toggleable panel parallel to spectrogram settings and cube colors. It loads, saves, updates, and deletes named snapshots from repo-tracked `data/dashboard-presets.json`; loading a preset writes `data/dashboard-settings.json`, updates the browser's allowlisted localStorage keys, and reloads so every module re-initializes from the selected snapshot. The first shipped preset is the current dashboard settings snapshot, including cube colors, spectrogram palettes, quality, layer toggles, ghost/cube offsets, and motion-control sliders.
- **Optional interruption layer** (`public/interruption/`, URL `?intrusions=1`): creates a fixed video element and fixed targeting canvas under the normal HUD overlays, plus a debug panel only when `intrusionDebug=1` or `D` is pressed. The layer injects/removes its own scoped stylesheet and leaves no DOM behind when disabled or destroyed.

Only the active K/C cards render; they become visible on a phrase trigger as the active K and active C labels pull together, fade out, and conjure the card cluster. The active live and ghost dots are elastically pulled toward one another but keep separated by their tethers; non-active labels remain visible. Card placement follows the ghost cube only, so gyro motion on the live cube does not jitter the cards. The 8-vertex/complex grids and legacy controls are populated but hidden via `.ovl-legacy`. The XENAKUBE title toggles chrome visibility with `body.ui-hidden`: connection controls, mode badges, state panels, bottom-right controls, move buffer, toasts, and active K/C cards hide, while the cube, rolling score, sieve, and non-active live K-vertex telemetry labels remain visible.

## Rolling-score brush rendering

Each note is rendered via a per-complex procedural brush (`COMPLEX_BRUSH` dispatch; reference `docs/archived/brushes.png`):

- C1 pizz = spatter
- C2 arco = rough wash
- C3 arco = watercolor
- C4 harm = airbrush halo
- C8 sul-pont trem = chalk grit

Gliss complexes C5/C6/C7 bypass per-note brushes — each chain (maximal run of same-voice + same-complex notes that pass the unified live-entry classifier; see `docs/dashboard-invariants.md` "Slide-vs-leap classifier consistency") is drawn as a single stroked Path2D (`drawGlissChain`) with `lineJoin = 'round'`, so the rect-body / slant-transition / rect-body polyline reads as one continuous brush stroke. The legacy `GLISS_GAP_MS = 25` ms (`constants.js`) is now a UDP-reorder fallback only — chain breaks fire on the per-note `chainStart` flag.

Brush vertical dimensions go through `bu(factor) = rollRowH * factor * ROLL_BRUSH_SCALE` where `rollRowH` is the device-px height of one semitone in the current viewport (recomputed every frame). This keeps brushes proportional across screen sizes — a 1.45-row chalk band stays 1.45 rows on a 1080p monitor and on a 13" MacBook. `ROLL_BRUSH_SCALE` (default 1.4) is the single global tuning knob.

Colours per complex: C1 amber, C2/C3 cobalt, C4 cyan, C5/C6/C7 magenta, C8 crimson. Velocity → opacity. Stochastic brush textures use a `mulberry32` stream seeded from `(voice, pitch, onsetMs)` so each note's speckle pattern is identical every frame.

Per-key FIFO queue for in-flight notes (`activeMidiNotes: Map<key, Array<entry>>`) — bridge legitimately emits overlapping noteons on the same pitch (C8 trem rebows, double-stop companion, humanPitch collisions) and the queue preserves each iteration as a distinct rendered note instead of overwriting. Watchdog finalises any active note stuck > 45 s.

Within-note dynamic shape (D70 + D71): brush half-height samples the per-voice CC 11 trace at each polygon vertex / particle's t — see `docs/dashboard-invariants.md` "Within-note dynamic shape fidelity" row.

Data source: `midi_echo` WS messages mirrored from Max; Phase E tier 3 will switch to TS-generated note lists once the phrase migration lands.

## Post-processing pipeline (Phase 3)

The cube scene runs through an `EffectComposer` chain in `public/js/cube-scene.js`. The composer is built once at module load and lives next to the renderer:

```
RenderPass(scene, camera) → UnrealBloomPass → OutputPass → canvas
```

`renderer.toneMapping = ACESFilmicToneMapping` and `renderer.toneMappingExposure = 1.0` are set on the WebGL renderer itself. Tone mapping + sRGB conversion are applied either by `OutputPass` (Med / High quality) or by the renderer directly (Low — composer bypassed). Both code paths honor the renderer's tone mapping setting, so flipping the picker only gates bloom + the composer overhead, not the colour curve.

Quality is a discrete tier — `setQuality('low' | 'med' | 'high')` — exposed by `cube-scene.js`, persisted in `localStorage('quality')` by `main.js`, defaulted to **Med** so a fresh user on a normal GPU sees the effect. Low is the explicit "weak GPU" escape hatch that skips the composer entirely.

| Tier | Composer | strength | radius | threshold |
|---|---|---|---|---|
| Low  | bypassed (direct `renderer.render`) | — | — | — |
| Med (default) | enabled | 0.32 | 0.30 | 0.90 |
| High | enabled | 1.45 | 1.05 | 0.42 |

Defaults are tunable in browser; `applyQualityPreset` mutates the live `bloomPass` parameters plus the K-halo opacity, base live/ghost edge opacity, adaptive-line opacity, and active-ring scale. The base live cube edge stays white at reduced opacity so it can support High-tier glow without fighting the adaptive contrast pass. Med is deliberately restrained so the cube gets a readable aura without washing the labels; High lowers the threshold and widens the blur enough to read as a distinct stage-glow mode. K/C vertex labels are assigned to a separate render layer and drawn after the base/composer pass, so `UnrealBloomPass` never blurs the text.

`#cube-contrast-layer` is a transparent SVG above `#cube-canvas` and below the K/C-to-sieve line overlay. `cube-scene.js` projects the same 3D endpoints and writes structural `<line>` strokes into it (live outer edge, live tetra lines, ghost outer edge, and K↔C line), while CSS applies `mix-blend-mode: difference` per stroke by default. This is the cheap adaptive-color path: each wire segment inverts whatever the browser has already composited underneath it, including rolling-score strokes and live-cube pixels under the ghost wireframe, without sampling DOM pixels in a shader. The cube colors panel can retint these strokes and adjust their effective SVG stroke widths; the WebGL base line width is also stored for renderers that honor `LineBasicMaterial.linewidth`.

The gizmo runs on its own `gizmoRenderer` and does **not** post-process — small UI controls don't want a glow halo. `composer.setSize` + `bloomPass.resolution.set` are wired into `resizeCube()` so the composer tracks viewport changes.

The picker DOM lives in `public/dashboard.html`'s `.ovl-br` cluster (`#qualityCtrl`), styled in `public/css/main.css` via `.quality-ctrl .q-btn{,:hover,.active}`, click-wired in `public/js/main.js`'s `applyQuality()`. The picker hides under `body.ui-hidden` along with the rest of the chrome so the title-toggle "performance mode" is unaffected.

Phase 4 brush migration (Canvas-2D → WebGL) will share this composer chain rather than build a second one — the rolling-score canvas stays separate but post-processing of the cube scene is the validated reference pipeline.

## Editing checklist

After editing `dashboard.html`, load `:3000` and verify the rolling score renders, active K/C labels merge into the K/C cards after a phrase trigger, and Zero Gyro works at 100 % and 50 % browser zoom. After interruption-layer edits, also verify `?intrusions=0` leaves no overlay DOM visible and `?intrusions=1&intrusionDebug=1` responds to `W`, `C`, `X`, `D`, and `T`.
