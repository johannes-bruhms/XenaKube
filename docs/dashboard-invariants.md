# Dashboard Visual Invariants — Full Enforcement Detail

> CLAUDE.md keeps a compressed summary of each invariant (claim + where + failure log). This file is the source of truth for *how* each invariant is enforced and *what* the failure logs surface. Read this file before changing any code that touches an invariant.

The dashboard has its own silent-failure surfaces analogous to the bridge's. Two pieces of code computing "the same thing" independently — pitch-axis math in `midiToY` vs cell layout in flexbox; gliss trajectory in white-line vs rolling-chain — drift apart on every refactor unless the contract is written down and tested at runtime. Every row below was added after a regression that took multiple iterations to fully fix; the invariant is what stops it coming back.

The optional interruption layer (`public/interruption/`, enabled by `?intrusions=1`) is deliberately outside the existing rolling-score, sieve, gliss, and white-triangle invariants. It may read cube-scene projection callbacks through `main.js`, but it must not mutate `triangle.js`, rolling-score note state, sieve layout, pitch-axis constants, or the existing invariant assertions. If it cannot project K/C points, it warns once and disables only its own targeting geometry.

| **Within-note dynamic shape fidelity** (D70 + D71) — for sustained complexes (C2/C3/C4/C8), the brush half-height at every polygon vertex AND every particle (Watercolor blobs, Airbrush pucks, Chalk specks) samples the per-voice CC 11 trace at that vertex's t.
