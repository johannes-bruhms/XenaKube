# Changelog

All notable changes to XenaKube are documented here.

**Entry format**: dated section per release/working-day; under it, `### Added / Changed / Fixed` headers; under each header, **terse bullets** — one or two sentences naming the user-visible change and the file(s) touched. Long rationale, root-cause analyses, and D-coded design narratives belong in `docs/revision_roadmap.md` (bridge / SWAM) or `docs/research_notes.md` (engine / dashboard). When in doubt, link rather than copy. Older entries below predate this discipline and are kept as-is.

- Removed low-expression onset masking from slow-start face gestures. Normal phrase starts now seed CC 11 through shared `ONSET_EXPRESSION_MIN`, so C8 on `D'`/yellow counterclockwise hairpins speaks immediately instead of ramping up from near-silent expression (`src/swam-mapping.ts`, `max/xk_swam.js`, `src/phrase-plan.ts`, `relay.js`, `docs/bridge-invariants.md`).
- Tightened C5/C6/C7 half-turn punctuation into a single short one-direction bend stroke with no target re-attack, and generated the shared gliss constants into Max so the bridge and TS planner stay aligned (`src/swam-mapping.ts`, `scripts/gen-max-include.js`, `max/xk_swam.js`, `src/phrase-plan.ts`, `test/max-bridge.test.ts`, `test/phrase-plan.test.ts`, `docs/bridge-invariants.md`).

- Fixed Bluetooth cube stream stalls and reduced gyro transport pressure. The dashboard now unit-normalizes GAN gyro events, coalesces outbound gyro to a latest-only relay queue, flushes pending gyro before `move` and `zero_gyro` messages, carries latest gyro inside a move if the low-priority gyro send is blocked, requests facelets-only bootstrap after connect, detects move-alive/gyro-stale splits, and the relay re-normalizes incoming gyro packets with explicit `[CUBE STREAM FAIL]` / `[CUBE GYRO FAIL]` / `[CUBE GYRO FORWARD FAIL]` / `[CUBE GYRO STALE]` / `[BLE GYRO DROP]` telemetry (`public/js/main.js`, `relay.js`, `test/transport-backpressure.test.ts`, `docs/dashboard-invariants.md`).

- Added relay-open gating to the Bluetooth cube flow. The Connect button now stays disabled while the relay WebSocket is down, active BLE forwarding is invalidated if the relay disconnects, and `[CUBE RELAY OFFLINE]` points to the Max `node.script relay-controller.js` start path instead of flooding gyro/move send failures (`public/js/transport.js`, `public/js/main.js`, `test/transport-backpressure.test.ts`, `docs/dashboard-invariants.md`).
- Made half-turn punctuation technique-aware. C1 half-turns now stay pizzicato, C4 force-writes harmonics, C5/C6/C7 render one shared-duration big/medium/small gliss, and the remaining complexes keep the bowed dyad punctuation (`src/swam-mapping.ts`, `max/xk_swam.js`, `src/phrase-plan.ts`, `test/max-bridge.test.ts`, `test/phrase-plan.test.ts`, `docs/bridge-invariants.md`, `docs/synthesis-bridge.md`, `docs/performance-model.md`, `docs/xenakube-operation-manual.md`).

## 2026-05-07

### Changed
- Reworked C2 tempo curve: turn-rate-aware exponential rate endpoints. Replaced `C2_TEMPO_LO/HI=0.9/2.2` multipliers + `rateDensityMultiplier(2)` baseRate with `C2_RATE_MIN=4`, `C2_RATE_MAX=17.5`, `C2_RATE_SPAN_RATIO=3.0`. Endpoints scale with `turnRatePressure()`: at turnP=0 the within-phrase rate range is `[4, 12]` notes/sec; at turnP=1 it's `[5.83, 17.5]`. Span ratio is held constant at 3× across all turn rates so the within-phrase accel/rit is always audibly dramatic, and the slow end of the lowest turn rate now reads as a clear cellistic 4 notes/sec instead of the previous 5.4. Curve is now **exponential in rate** (geometric: `rate(u) = lo × (hi/lo)^u` for accel) instead of linear — linear-in-log-rate matches musical tempo perception so accel/rit feels uniformly smooth rather than back-loaded. Telemetry log gained `rate=Lo→Hi n/s` and `turnP=N.NN` so the actual rate range and turn-pressure are visible in `[print xk_swam]`. Mirror in `src/phrase-plan.ts`. Bumped `C2_DOUBLE_STOP_PROB` from 0.20 to 0.30 so dyads register more often during a run.
- Added intentional double-stops to C2 directional run via per-note dynamic CC 81 toggle. `COMPLEX[2].bowPoly` baseline stays `MONO_POLY_RELEASE` (asserted per `/xk/voice` in handleVoice). `phraseC2` now flips CC 81 PER NOTE: monophonic notes write `MONO_POLY_RELEASE` (SWAM auto-releases on next noteOn → smooth legato, no chord), intentional double-stop notes (`C2_DOUBLE_STOP_PROB = 0.20`, first note always solo) write `DOUBLE_HOLD` so the main + companion (picked via `doubleStopCompanion`, cellistic 3rd/4th/5th/6th/octave intervals) sustain together as a held dyad. Race-free: each note's task writes its own CC 81 before any noteOns, so mode is correct at every noteOn time regardless of when previous noteOff fires. Double-stop notes have `noteDurMs` capped at `spacingToNext - C2_DOUBLE_STOP_GUARD_MS = spacingToNext - 5` so the dyad's noteOffs fire before the next noteOn. Result: monophonic transitions structurally cannot chord (SWAM auto-release in MONO_POLY_RELEASE); double stops are heard exactly when intended. Telemetry log adds `doubles=D/N`. Static guard in `test/max-bridge.test.ts` asserts the baseline mode + that phraseC2 writes both modes via `CC.BOW_POLYPHONY` + uses `doubleStopCompanion`. Mirrored in `src/phrase-plan.ts` so the audit's expected counts include companion noteons.
- Added C2 CC 11 floor `C2_MIN_PEAK_EXPR = 46` in `max/xk_swam.js` (mirrored in `src/phrase-plan.ts`). Applied as a minimum on `inst.peakExpr` for C2 only, immediately after the standard intensity/face/rate computation in `handleVoice`. Ensures the run's soft endpoint (`0.55 × peakExpr`) always renders above CC 11 = 24 — at low K-intensities (ppp/pp/p) where natural peakExpr would dip below ~44 the floor lifts both endpoints together, preserving the 0.55→1.0 swing shape. Mid/high intensities pass through unchanged.
- Restored C2 (OrderedCloudAscDesc) directional-run identity. Pre-rewrite `phraseC2` was a slow legato cloud with 50% double-stops + phrase-wide CC 11 arc, audibly identical to C3 (constant-register cloud). New `phraseC2` in `max/xk_swam.js` and the mirror in `src/phrase-plan.ts` is a rate-driven directional scalar run (~6 notes/sec × `rateDensityMultiplier(2)` × duration) with strict directional sieve walk, no double-stops. `ARC_COMPLEXES` drops C2; the phrase arc is realized PER-NOTE via velocity, CC 17 (Bow Pressure), CC 11 (Expression), and `inst.bowPosBase` migration shaped by `phraseArcDirection(inst)` (cresc/dim/hairpin), 0.55→1.0 swing depth — mirrors how real cellists shape a run by varying bow pressure / position / speed per stroke. **Within-phrase tempo curve** (`buildC2Tempo`): each C2 phrase has accelerando / ritardando / accel-rit / rit-accel motion coupled to arc direction (cresc→accel, dim→rit, hairpin-up→accel-rit, hairpin-down→rit-accel, no-arc→random); tempo bounds `[C2_TEMPO_LO=0.9, C2_TEMPO_HI=2.2]` give a slow end ≈ 5.4 notes/sec and a fast end ≈ 13 notes/sec. **Emergent articulation** (replaces the earlier regime-based detache/legato hybrid): per-note "intrinsic ring time" `r ~ uniform[C2_RING_MIN_MS=120, C2_RING_MAX_MS=320]`; scheduled noteOff = `min(r, localSpacing + LEGATO_OVERLAP_MS)`. Default is legato (canonical 20 ms overlap, always true at fast tempi where spacing < 120 ms); detache emerges only at slow tempi when the rolled ring is shorter than localSpacing — same way real cello playing produces gaps only when the bow outpaces finger placement. Per-phrase telemetry `[phraseC2 RUN] inst=N count=N tempo=accel|rit|accel-rit|rit-accel|rand-* spacing=Smax→Smin ms detache=D/N arcDir=... dur=Ds` so a future regression is visible immediately. Bridge invariant row `Phrase dynamic arc` and `CLAUDE.md` summary updated.

### Fixed (D58 per-complex leap tolerance)
- **D58 — `MAX_LEAPS_BY_COMPLEX` per-complex leap tolerance.** User report 2026-04-30: "top half ones that start high and drop down. those played as two regular notes with leaps, meanwhile the lower half (start low and gliss up) seemed to work fine, even the last one that gliss back down." Lower-half phrases stay in the C/G/D overlap zone (36–69) where almost every adjacent pair shares a string.

### Fixed (D56 GLISS SYNC FAIL, D57 pizz dynamics)
- **D56 — `chainStart` preservation across note finalisation.** User report 2026-04-30: `GLISS SYNC FAIL voice=1 complex=5 line=490.26px chain=651.29px drift=161.03px linePitch=61.00 chainPitch=52.00`. Root cause: `rolling-score.js noteOff` and `_watchdogTick` were pushing finalised entries into `finishedMidiNotes` WITHOUT copying the `chainStart` flag. `_findActiveGlissChain` walks finished + active evts to rebuild the latest chain; for finished entries, `evts[i].chainStart === undefined` → falsy → the chain rule reverted to gap-only classification (`evts[i].onsetMs - prevOff > GLISS_GAP_MS`). For voice-steal-driven phrase boundaries (synchronous `noteoff(old) → noteon(new)`, gap ≈ 0 ms), the gap test never fired → the chain silently spliced the OLD phrase's segments onto the new phrase, while triangle's `lineNotes` (which operates on live state via `_findGlissLine` / `_hasActiveGliss`, not finished history) correctly tracked only the new phrase. Result: multi-semitone disagreement on every voice steal during gliss play.
  - **Fix**: copy `chainStart` onto the finalised entry. Two locations (`noteOff` + `_watchdogTick`); single source of truth (the original entry's flag).
  - **Forensic enrichment**: the GLISS SYNC FAIL log line now includes segment count, latest segment's `t0`/`dur`/`p0`/`p1`, the chainNode summary (`pitch*` marks `chainStart=true`), and `nowMs` so a future regression's stale-source side is identifiable from the log alone. ### Fixed (D54 bow-position flap, D47 Phrase Arc Phase 2)
- **D54 — `handleExprTilt` EMA + bow-position flap telemetry.** User report 2026-04-30: "bow/pizz position jitters like crazy, oscillating between 2 values, especially for sustained sounds — as if there are two streams of data fighting for space." - **SWAM bridge — portamento regression + KS vel-0 note-off reset.** Two bugs that landed together in the v3 refactor:
  - `cancelPhrase()` was hard-releasing every active note at the top of each `handleVoice`, which emptied `state.activeNotes` before the next phrase's `legatoNote()` could overlap it. SWAM triggers portamento on noteOn-before-noteOff — with no overlap, no portamento. Fix: `cancelPhrase(preserveLegatoTail)` keeps only the most recent active note when the incoming complex is legato-capable (C2/3/5/6/7); earlier notes are still released to avoid stuck-note accumulation. Hard-release (`preserveLegatoTail` unset) is used from `bang()` / panic / `t-perm`. New `LEGATO_COMPLEX` table declares which complexes own the preserve path. Pizz/harmonics/ponticello (C1/4/8) stay hard-cancelled — they're re-bow / short-gate, not legato.
  - `keyswitch()` was sending note-off with velocity 0. SWAM v3.10 reads KS note-off velocity and interprets vel 0 as "option 0 = OFF" — so ~50 ms after every turn into C4, Harmonics snapped from Octave back to Off (same for C8 Tremolo Fast → Off). Symptom: "flash briefly then off within the same turn." Play Mode escaped notice because its option 0 is "bow" — flipping to bow after pizz/col is a silent no-op for most turns. Fix: note-off velocity now matches the note-on velocity, so the latch survives.
- **SWAM bridge — v3.8 → v3.10 KS migration (D24/D27, root cause of "harmonics & tremolo never fire").** The bridge's `KS` map was built against the v3.8 reference but the running VST is v3.10. v3.10 renumbered the KS plane and converted most controls from latch-toggle to **velocity-selectors**. Symptoms: C4's "harmonics on" was actually writing v3.10's *Tremolo Mode* (KS 33), and C8's "tremolo on" was writing an *unassigned* KS (KS 34) — so neither ever sounded.
